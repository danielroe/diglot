---
title: Astro site
description: Run a small Astro site in English, German and Japanese, built from diglot records, and review its translations in x18n.
---

`examples/astro` in the diglot repository is a small [Astro](https://astro.build) site, written in English and translated into German and Japanese. Its pages are Markdown and MDX files in a content collection. The [Astro integration](/integrations/astro) builds their translations from the records in `translations`, a translations repository that lives inside the site, so you see both sides of the workflow in one place. You can also review its translations in the [x18n dashboard](/review-ui/overview).

## Run it

Install the dependencies from the root of the diglot repository, so that the example uses the local diglot packages. Then start the dev server from the example's directory:

```bash
pnpm install
cd examples/astro
pnpm dev
```

When you build the site with `pnpm build`, you get eleven pages in `dist`. The four English pages live at `/`, `/guide/`, `/components/` and `/about/`, their German versions under `/de/`, and three Japanese pages under `/ja/`.

## What it contains

| File | Purpose |
| --- | --- |
| `astro.config.mjs` | The `mdx()` and `diglot()` integrations, and the `i18n` locales: `en` as the default, `de` and `ja` |
| `src/content.config.ts` | The `docs` collection, loaded with `diglotLoader()` |
| `src/content/docs/` | The English source pages, three in Markdown and one in MDX |
| `src/content/docs/de/about.md` | A German page translated by hand |
| `src/components/Card.astro` | The component that the MDX page uses |
| `src/pages/[...slug].astro` | One route for every page in every locale |
| `src/i18n.ts` | The navigation and the language menu of each page |
| `src/layouts/Layout.astro` | The dark theme, with the navigation and the language menu |
| `translations/diglot.config.ts` | The locales `de` and `ja`, and `parser: 'satteri'` |
| `translations/sources.yml` | One source, the English pages of the site |
| `translations/x18n.config.ts` | The diglot plugin for the x18n dashboard |
| `translations/de`, `translations/ja` | The translation records |

## What it shows

German has a record for every segment of the home page, the guide and the components page. The about page is translated by hand. Because `de/about.md` already exists in the collection, the loader keeps it and adds no translation of its own.

The Japanese records are machine translations. The last section of the Japanese guide has no records, so its text stays in English while the rest of the page is Japanese. The about page has no Japanese records at all, so there is no `/ja/about/`. When you open the about page, the language menu only offers English and German.

The components page is MDX. It imports a `Card` component and uses an expression, and the translated pages render both, with the card titles translated, because the default policy lists the `title` of a card as prose. The home page links to the guide with a relative link, `guide/`, so the link leads to the guide of the same language. URLs are protected from translation, which is why the example avoids absolute links between its pages.

## Work with the translations

The `translations` directory is a regular translations repository, so the [`diglot` command](/workflow/cli/overview) works on it. `pnpm translations:extract` splits the English pages into segments again after you change one, and `pnpm translations:status` extracts them and prints how much of each language is translated:

```bash
pnpm translations:status
```

The three untranslated German segments in the output are those of the about page, which the site translates by hand:

```text
de
  site: 23 segments, 247 words, 83.4% of words reviewed (edited 20, untranslated 3)
ja
  site: 23 segments, 247 words, 0.0% of words reviewed (machine 18, untranslated 5)
```

## Review in the dashboard

`pnpm translations:ui` extracts the segments, exports the English pages for the usage view, and starts the x18n dashboard on a free port from `9999`. The terminal shows the address and an auth code to sign in. In the dashboard, every segment is a key, and the 18 Japanese machine translations are waiting for review.

When you approve a translation, its record in `translations/ja/segments/` becomes verified, and the approval is added to `translations/.x18n/reviews.yml`. When you edit a translation, the record changes too, and while `pnpm dev` runs, the page shows the new text without a restart.
