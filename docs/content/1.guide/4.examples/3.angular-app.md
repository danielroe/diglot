description: Run a small Angular app in English, French and Turkish that applies diglot bundles in the browser and while it prerenders, and review its translations in x18n.
---

`examples/angular` in the diglot repository is a small [Angular](https://angular.dev) app, written in English and translated into French and Turkish. Its pages are Markdown files, and the [Angular recipe](/guide/how-to/translate-an-angular-app) applies the bundle of `translations`, a translations repository that lives inside the app, when a page loads. The pages under `/en`, `/fr` and `/tr` are prerendered, and the browser picks up the prerendered documents without fetching them again. The language picker pages under `/picker` are prerendered in English, and readers choose French or Turkish in the browser. You can also review its translations in the [x18n dashboard](/review-ui/overview).

## Run it

Install the dependencies from the root of the diglot repository, so that the example uses the local diglot packages. Then start the dev server from the example's directory:

```bash
pnpm install
cd examples/angular
pnpm start
```

`pnpm start` and `pnpm build` run `pnpm translations:build` first, which runs `diglot extract` and `diglot build`, so the policy snapshot and the bundle always match the pages. The dev server doesn't watch the translations repository, so after you edit a record, run `pnpm translations:build` and reload the page. When you build the app with `pnpm build`, you get twelve pages in `dist`: `/en`, `/en/guide` and `/en/about`, the same three under `/fr` and `/tr`, and the three pages of the language picker under `/picker`, plus a redirect at `/`.

## What it contains

| File | Purpose |
| --- | --- |
| `src/app/diglot-store.ts` | Fetches each bundle once and applies it to a document, and hands documents from the server to the browser |
| `src/app/diglot-document.ts` | `diglotDocument()`: a document in the current language, as signals |
| `src/app/language.ts` | `DIGLOT_LOCALE`, read from a route parameter or a signal |
| `src/app/app.routes.ts` | The `/:locale` and `/picker` routes, each with its own way to choose the language |
| `src/app/app.routes.server.ts` | The parameters that prerender each page under `/en`, `/fr` and `/tr`, and the English pages under `/picker` |
| `src/app/page.ts`, `page.html`, `page.css` | The page component: `diglotDocument()`, the navigation, the language menu and the partly-translated notice |
| `src/app/markdown.ts` | Renders a page with marked and points its relative links to the same locale |
| `src/content/docs/` | The English source pages |
| `translations/` | The translations repository: `diglot.config.ts`, `sources.yml` and the French and Turkish records |
| `translations/x18n.config.ts` | The diglot plugin for the x18n dashboard |
| `angular.json` | Serves the bundle under `/translations` and the source pages under `/docs` |

## What it shows

The app shows both ways to choose a language, and a link at the top of each page switches between them. Under `/en`, `/fr` and `/tr`, the language is in the URL, read by `provideRouteLocale()`, and every language is prerendered. Under `/picker`, the buttons of the language menu set a signal, so the URL stays the same, only the English pages are prerendered, and a reload goes back to English.

The French and Turkish records translate every segment except one paragraph of the about page. That paragraph stays in English, and the page shows a notice that it is only partly translated, which comes from the `report` of `diglotDocument()`. The home page links to the guide with a relative link, `guide`, and the app points it to the guide of the same language. URLs are protected from translation, so relative links keep readers in their language.

## Work with the translations

The `translations` directory is a regular translations repository, so the [`diglot` command](/workflow/cli/overview) works on it. `pnpm translations:extract` splits the English pages into segments again after you change one, `pnpm translations:build` also builds the bundles that the app reads, and `pnpm translations:status` extracts the segments and prints how much of each language is translated:

```bash
pnpm translations:status
```

The untranslated segment in the output is the paragraph of the about page:

```text
fr
  app: 16 segments, 163 words, 79.8% of words reviewed (edited 15, untranslated 1)
tr
  app: 16 segments, 163 words, 79.8% of words reviewed (edited 15, untranslated 1)
```

## Review in the dashboard

`pnpm translations:ui` extracts the segments, exports the English pages for the usage view, and starts the x18n dashboard on a free port from `9999`. The terminal shows the address and an auth code to sign in. In the dashboard, every segment is a key with its French and Turkish translations.

When you approve a translation, its record becomes verified, and the approval is added to `translations/.x18n/reviews.yml`. When you edit a translation, the record changes too. The app reads the bundles, so run `pnpm translations:build` and reload the page to see the new text.
