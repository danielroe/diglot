---
title: Define sources
description: Point diglot at the repositories, refs and directories whose documentation you translate.
---

A source tells diglot where to find documents. You can have as many as you like, for example one per branch of a documentation repository, and each gets its own manifest. Sources live in `sources.yml`, either as a list or under a `sources` key.

```yaml [sources.yml]
sources:
  - name: nuxt-main
    repo: nuxt/nuxt
    ref: main
    path: .diglot/checkouts/nuxt/nuxt
    dir: docs
  - name: nuxt-4.x
    repo: nuxt/nuxt
    ref: 4.x
    path: .diglot/checkouts/nuxt/nuxt
    dir: docs
```

## Fields

| Field | Description |
| --- | --- |
| `name` | Required. Letters, digits, dots, dashes and underscores. It names the manifest, so it must be unique. |
| `repo` | `owner/repo` on GitHub. Used to fetch the source when it isn't on disk yet. |
| `ref` | The git ref to read. Without it, diglot reads the working tree at `path`. |
| `path` | The local checkout, relative to the config file. |
| `dir` | The directory inside the checkout. Defaults to the root. |
| `include` | Glob patterns relative to `dir`. Defaults to `**/*.md` and `**/.navigation.yml`. |
| `exclude` | Glob patterns relative to `dir` to leave out. |

## Reading at a ref

With a `ref`, diglot resolves it to a commit and reads the files from git, so the working tree of your clone doesn't matter. The manifest records that commit. Without a `ref`, diglot reads whatever files are on disk, which suits a source you are editing locally.

## Checkouts

`diglot checkout` and the Action make sure every source has a checkout. If the directory at `path` doesn't exist, they create a bare repository there and fetch the refs of all sources that share it, one commit deep. If you leave out `path` but set `repo`, the default is `.diglot/checkouts/<repo>`. Several sources can point at the same checkout, as the two above do, and diglot fetches each ref once into it.

Fetching needs a `ref` for every source that uses the checkout. `extract` and `diff` read from the path as it is and don't fetch, so run `checkout` first, or let the Action do it. A source without a `path` can't be extracted.

## Narrowing what is translated

Use `dir` to translate only a documentation folder, and `include` and `exclude` to refine within it:

```yaml
sources:
  - name: guide
    repo: acme/widgets
    ref: main
    path: ../widgets
    dir: docs
    include:
      - guide/**/*.md
    exclude:
      - guide/changelog.md
```

Patterns are matched against paths relative to `dir`.
