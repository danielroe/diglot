---
title: Configure diglot
description: Set the locales, parser, output directories and machine translation options in diglot.config.ts.
---

Everything about a translations repository that isn't a source or a locale file lives in `diglot.config.ts`. The CLI and the Action load it from the working directory, trying `diglot.config.ts`, `diglot.config.mts`, `diglot.config.js` and `diglot.config.mjs` in that order. Without a config file, the locales list is empty and nothing is translated.

Wrap the object in `defineConfig` so your editor knows the options:

```ts [diglot.config.ts]
import { defineConfig } from '@diglot/core'

export default defineConfig({
  locales: ['fr'],
  glossary: 'glossary.yml',
  mt: {
    model: 'anthropic/claude-sonnet-5.5',
    subject: 'the documentation of Nuxt, a Vue web framework',
    batch: 'page',
    qaRetries: 1,
  },
})
```

## Options

| Option | Default | Description |
| --- | --- | --- |
| `locales` | none | The target locales, as BCP 47 tags such as `fr`, `ja` or `pt-BR`. Any other value is rejected when the config loads. |
| `sources` | `sources.yml` | The path to a sources file, or the list of sources itself. See [sources](/guide/how-to/sources). |
| `parser` | `comark` | The markdown parser used for extraction: `comark`, `mdast` or `satteri`. The first two read MDC components, while `satteri` reads markdown without MDC. See [adapters](/adapters/overview#choosing-one). |
| `policy` | the default policy | Overrides for what counts as prose. See [segments](/guide/concepts/segments). |
| `diff` | `threshold: 0.5`, `margin: 0.1` | How segments are paired when a source changes. See [keeping in sync](/guide/concepts/keeping-in-sync). |
| `outDir` | `dist` | Where `build` writes the locale bundles. |
| `stateDir` | `.diglot` | Where manifests and other generated state live. |
| `glossary` | `glossary.yml`, when the file exists | A glossary shared by every locale. |
| `mt` | `{}` | Machine translation settings. |

The `.navigation.yml` files in your sources are always extracted by the comark parser, whichever `parser` you choose for markdown, so a mixed source keeps its titles translated. `.mdx` files are always extracted by the mdast adapter, because comark doesn't read MDX.

`parser: 'satteri'` needs the `satteri` package, which isn't installed with the CLI. Add it next to the CLI:

```bash
pnpm add -D satteri
```

The [Action](/workflow/action/overview) installs it on its own when `parser` is `satteri`.

## Machine translation options

| Option | Default | Description |
| --- | --- | --- |
| `model` | `DIGLOT_MT_MODEL` | A model id for the [Vercel AI Gateway](https://vercel.com/ai-gateway), such as `anthropic/claude-sonnet-5.5`. |
| `subject` | `technical documentation` | What is being translated. It goes into the prompt, so a precise subject such as "the documentation of Nuxt, a Vue web framework" gives better translations. |
| `batch` | `page` | Send each page's segments in one request, or give a number to send that many segments per request. |
| `qaRetries` | `1` | How often to retry a segment that fails an error-level QA check before rejecting it. |

The Action's `model` input overrides `mt.model`. See [Machine translation](/machine-translation/overview) for how these options are used.
