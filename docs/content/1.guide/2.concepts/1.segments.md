---
title: Segments
description: Understand which parts of a markdown document diglot translates and how it classifies them.
---

A segment is the smallest piece of a document that diglot translates on its own. When it reads a document, a parser adapter walks the content and turns every unit that carries prose into a segment, so a long page becomes a list of headings, paragraphs, list items and so on, in document order.

Working at this size is what lets diglot react to small edits. If you change one sentence in a page of fifty paragraphs, one segment changes and the other forty-nine keep their translations.

## What counts as a segment

Each segment has a kind that says where it came from:

| Kind | Source |
| --- | --- |
| `heading` | A heading of any level |
| `paragraph` | A paragraph outside any list, quote or component |
| `list-item` | The text of a list item |
| `table-cell` | A table header or data cell |
| `blockquote` | The text of a blockquote |
| `component-slot` | Prose inside a component, such as a callout or a card body |
| `html-block` | Text inside HTML elements listed in the policy, such as `summary` or `figcaption` |
| `image-alt` | The `alt` text of an image |
| `prop` | A prose prop of a component, such as the `title` of a card |
| `frontmatter` | A prose value in frontmatter, such as `title` or `description` |
| `code-label` | A code block label that reads as prose, such as `Directory Structure` |
| `code-comment` | One line of prose in a code comment |
| `navigation` | A prose key of a `.navigation.yml` file |

Code blocks themselves, inline code, URLs and component names are never translated. They are protected as [placeholders](/guide/concepts/skeletons-and-hashes). A unit with no letters outside its placeholders has nothing to translate, so it carries zero words and is left alone.

## Markdown and plain segments

Segments come in two formats. A `markdown` segment may contain emphasis and links, while a `plain` segment is a single line of text with no markup. Props, frontmatter values, code labels, code comments and navigation titles are plain. A translator or a model may not add markdown to a plain segment, and the [validation rules](/core/validation) enforce that.

## The policy decides what is prose

Which props, containers and frontmatter paths carry prose depends on the components your documentation uses, so it is configurable. The default policy targets Nuxt UI and MDC documentation:

- Props: `title` on `read-more`, `video-accordion`; `title` and `description` on `card`; `label` on `u-button`; `name` on `collapsible`.
- Layout containers whose paragraphs stay plain paragraphs: `steps`, `card-group` and `code-group`.
- HTML elements whose text is translated: `summary`, `div`, `details`, `figcaption`, `dt` and `dd`.
- Frontmatter paths: `title`, `description`, `navigation.title`, `head.title`, `links[].label`, `seo.title` and `seo.description`.
- `.navigation.yml` keys: `title`, `titleTemplate` and `description`.
- Comments in fenced code blocks are extracted.

You override any of these with `policy` in the [configuration](/guide/how-to/configure), and [the policy reference](/core/policy-and-config) lists each field.

## Context

Every segment records where it came from: the file, the headings above it, its index in the file, the containers around it, and a detail such as the heading tag, the prop name or the code language. The context travels with the segment but is not part of its identity, so moving a paragraph under another heading doesn't change its hash. Each segment also records the lines it came from, which tools use to point a reviewer at the source.
