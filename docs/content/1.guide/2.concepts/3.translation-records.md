---
title: Translation records
description: Learn what a translation record contains and why one file per locale and hash is stored in git.
---

A record is one translation of one source segment into one locale. It is a small JSON file at `<locale>/segments/<hh>/<hash>.json`, where `<hh>` is the first two characters of the hash.

Because records are plain files in git, a translation has a history, an author and a review like any other change. A pull request shows exactly which sentences were translated, edited or rejected.

## Fields

A record looks like this. The values are an illustration of the shape and not output from a real run.

```json [fr/segments/87/87ecf1244d975205.json]
{
  "hash": "87ecf1244d975205",
  "source": "Nuxt is powered by {0}Nitro{/0}, and {1} is built in.",
  "text": "Nuxt est propulsé par {0}Nitro{/0}, et {1} est intégré.",
  "origin": "mt",
  "review": "none",
  "derived": "fresh",
  "mt": {
    "model": "anthropic/claude-sonnet-5.5",
    "promptVersion": "1",
    "candidate": "Nuxt est propulsé par {0}Nitro{/0}, et {1} est intégré."
  },
  "updatedAt": "2026-01-01T00:00:00.000Z"
}
```

| Field | Meaning |
| --- | --- |
| `hash` | The identity of the source [skeleton](/guide/concepts/skeletons-and-hashes). It must match the file name. |
| `source` | The source skeleton, so a reviewer can read the record on its own. |
| `text` | The translated skeleton. |
| `origin` | Who produced the current text: `mt` for a machine, `tm` for a translation memory, `human` for a person. |
| `review` | What a person has done to it: `none`, `edited`, `verified` or `rejected`. |
| `derived` | How it relates to `prev`: `fresh` has no predecessor, `carry` copied its text, `update` was derived from it. |
| `prev` | The hash of the record this one evolved from. Required when `derived` is `carry` or `update`. |
| `salt` | The context salt of the source segment, when its hash is salted. |
| `mt` | The model, the prompt version and the unedited machine output (`candidate`). |
| `by` | The GitHub login of the last editor. |
| `verifiedBy` | `{ by, at }` for the person who verified the text. Required when `review` is `verified`. |
| `rejectedBy` | `{ by, at }` for the person who rejected it. Required when `review` is `rejected`, and allowed only then. |
| `updatedAt` | An ISO 8601 timestamp. |

Records are validated whenever they are read or written. An unknown key, a hash that is not 16 hexadecimal characters or a missing required field is an error, and `diglot validate` reports it.

## Why the machine candidate is kept

When a model writes a record, it stores its unedited output in `mt.candidate`. If a reviewer then edits `text`, the difference between the two shows how much of the draft needed correcting. `editRatio` in [`@diglot/core`](/core/records) computes that share.

## Records are not segments

A record exists only for hashes that have been translated. A hash with no record is untranslated, and a record whose hash no source uses any more is *unused*. Unused records stay in git, but bundles leave them out by default.
