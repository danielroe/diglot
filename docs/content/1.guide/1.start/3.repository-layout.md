---
title: Repository layout
description: See which files a diglot translations repository contains and which of them you edit by hand.
---

A translations repository holds configuration that you write, records that people and machines write, and state that diglot generates. Keeping them apart in your head makes it clear what belongs in review and what you can regenerate.

```text
diglot.config.ts
sources.yml                      repositories, refs and directories that feed the corpus
glossary.yml                     optional terminology shared by every locale (x18n shape)
<locale>/
  glossary.yml                   terminology for this locale
  style.yml                      style and typography rules
  locale.yml                     machine translation switch and review metrics
  segments/<hh>/<hash>.json      one record per locale and hash
.diglot/manifest/<source>.json   source segments per file, one entry per line
.diglot/policy.json              snapshot of the extraction policy
dist/<locale>.json               built bundle: { version, locale, records }
```

## Files you write

`diglot.config.ts` and `sources.yml` define what is translated and into which locales. The files inside a locale directory (`glossary.yml`, `style.yml` and `locale.yml`) steer translation for that locale. Each is optional, and the [glossary and style guide](/guide/how-to/glossary-and-style) explains them.

## Records

Every translation is a JSON file at `<locale>/segments/<hh>/<hash>.json`. These files are the product of the repository: reviewers read them in pull requests, and the Action writes them. Each one is serialised with a fixed key order and a trailing newline, so diffs stay small. See [translation records](/guide/concepts/translation-records) for the fields.

## Generated state

Everything under `.diglot/` and `dist/` is derived. The state directory holds more than the manifests:

| Path | Content |
| --- | --- |
| `.diglot/manifest/<source>.json` | The segments of each file of a source at its last extraction |
| `.diglot/policy.json` | A snapshot of the extraction policy, which servers restore to extract segments the same way |
| `.diglot/lineage.json` | For each live hash, up to five earlier hashes it evolved from, written by the Action |
| `.diglot/rejected/<locale>.json` | Segments whose machine translation failed QA, with the reasons, written by the Action |
| `.diglot/checkouts/<repo>` | Bare repositories fetched for sources that have a `repo` and no `path` |
| `.diglot/sources/<source>` | Plain files exported by `diglot checkout` |

Commit the manifests, the policy snapshot, the lineage and the rejections. The next run compares against the manifests, the lineage and the rejections, and a server needs the policy snapshot to apply translations at runtime. The checkouts and exported sources are caches, so keep them out of git. Change the locations with `stateDir` and `outDir` in the [configuration](/guide/how-to/configure).

## Bundles

`dist/<locale>.json` is what your documentation site reads. The [CLI](/workflow/cli/build) and the [Action](/workflow/action/inputs-and-outputs) write it, and you can turn it off in the Action with `build-dist: false` when you build bundles elsewhere.
