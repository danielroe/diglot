An adapter connects diglot to a markdown parser. It does two jobs: it extracts segments from a document, and it applies translations back to the document. The core never parses markdown itself, so each adapter decides how a parser's tree maps to [segments](/guide/concepts/segments).

| Package | Parser | Use it for |
| --- | --- | --- |
| [`@diglot/comark`](/adapters/comark) | [comark](https://comark.dev) | Comark documents, and `.navigation.yml` files |
| [`@diglot/mdast`](/adapters/mdast) | remark with `remark-gfm`, `remark-frontmatter` and `remark-mdc` or `remark-mdx`, or [Sätteri](https://satteri.bruits.org) | MDX, and Astro, Docusaurus, Starlight or plain markdown sources |
| [`@diglot/code`](/adapters/code) | A tokenizer per language | The comments of fenced code blocks, used by both adapters |

## Choosing one

Set `parser` in the [configuration](/guide/how-to/configure) to `comark` (the default), `mdast` or `satteri`. The CLI and the Action then use it for every markdown file of every source. `satteri` is the mdast adapter with [Sätteri](/adapters/mdast#parsers) as its parser, for sources that don't use MDC, such as the pages of an [Astro site](/integrations/astro). Two kinds of files don't follow the setting: `.navigation.yml` files are always handled by the comark package, and `.mdx` files always by the mdast adapter, because comark doesn't read MDX. The mdast adapter reads them with Sätteri when `parser` is `satteri`, and with remark otherwise.

`comark` and `mdast` both read MDC. They return the same segments with the same hashes for almost every document, which keeps your records valid if you switch from one to the other. The known exceptions are braces and HTML comments in running text, which the two split differently, so after a switch those segments need a new translation. They differ in what they give you when you apply translations:

| | comark | mdast |
| --- | --- | --- |
| Input to `extract` | A parsed document from `parse(source)` | The markdown string |
| Output of `apply` | A translated document, which you `render` to markdown | The translated markdown string |
| Positions | Lines of the enclosing top-level block, for documents from `parse` | Exact lines of the node |
| Preserves untouched text | The tree is re-rendered | Everything outside translated units is preserved byte for byte |

Pick the adapter that matches the pipeline of your site. If your renderer works on a comark tree, apply translations there and avoid a round trip through markdown. If it consumes markdown or an mdast tree, use mdast.

## Code comments

Both adapters use `@diglot/code` to extract prose comments from fenced code blocks, unless the policy sets `codeComments` to `false`.
