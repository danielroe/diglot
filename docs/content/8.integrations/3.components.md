title: Vue, React and Svelte
description: Translate the text of your components without keys, with a Vite plugin that extracts it at build time and a small runtime for each framework.
---

`@diglot/components` translates the text you write in Vue, React and Svelte components. There are no keys and no `t()` calls: you write plain text, and at build time a Vite plugin makes each run of text a [segment](/guide/concepts/segments), rewrites the component to render it through a small runtime, and loads the translations from the records of a translations repository. The same text has one hash wherever it appears, so it is translated once.

::package-info{name="@diglot/components" directory="packages/components"}
::

Each framework needs its parser: `@vue/compiler-sfc` for Vue, which comes with `vue`, `oxc-parser` for React, and `svelte` for Svelte 5.

## Prepare the translations repository

List your components in a source, as you would list Markdown files, and run [`diglot extract`](/workflow/cli/extract) to write their segments to a manifest. The translations repository needs the parsers of your frameworks installed for that:

```yaml [translations/sources.yml]
sources:
  - name: app
    path: ..
    include: ['src/**/*.{vue,tsx,svelte}']
    exclude: ['**/*.test.*']
```

From there the segments of your components are like any others: machine translation and review work on them, and [x18n](/review-ui/overview) lists them and finds each one in the files that `diglot checkout` exports.

## Add the plugin

Add the plugin to your Vite config, before the plugin of your framework. `translations` is the directory of the translations repository, relative to the Vite root, and `sourceLocale` defaults to `en`:

```ts [vite.config.ts]
import diglot from '@diglot/components/vite'
import vue from '@vitejs/plugin-vue'
import { defineConfig } from 'vite'

export default defineConfig({
  plugins: [diglot({ translations: './translations' }), vue()],
})
```

The plugin reads every component under the Vite root and builds a catalog for each locale of `diglot.config.ts` from its records. Each translation is [validated](/core/validation) against its segment first: one that fails, or that a reviewer rejected, is left out, and its text stays in the source locale. Each catalog is its own chunk, loaded when your app switches to its locale.

## Create the locale state

`virtual:diglot` holds the source locale and a loader for each catalog. Pass it to `createDiglot()` from the entry of your framework:

```ts [Vue: src/main.ts]
import { createDiglot } from '@diglot/components/vue'
import translations from 'virtual:diglot'

const diglot = createDiglot({ ...translations, locale: 'fr' })
createApp(App).use(diglot).mount('#app')
```

```tsx [React: src/main.tsx]
import { createDiglot, DiglotProvider } from '@diglot/components/react'
import translations from 'virtual:diglot'

const diglot = createDiglot({ ...translations, locale: 'fr' })
createRoot(document.getElementById('root')!).render(<DiglotProvider diglot={diglot}><App /></DiglotProvider>)
```

```svelte [Svelte: the root component]
<script>
  import { createDiglot, setDiglot } from '@diglot/components/svelte'
  import translations from 'virtual:diglot'

  setDiglot(createDiglot({ ...translations, locale: 'fr' }))
</script>
```

`await diglot.setLocale('de')` loads the catalog of a locale and switches to it, and every component re-renders. Deeper in your app, `useDiglot()` in Vue and React and `getDiglot()` in Svelte return the state for a locale switcher. `diglot.subscribe(listener)` calls `listener` after each change, for example to keep `<html lang>` in step. For the types of `virtual:diglot`, add `@diglot/components/client` to `types` in your `tsconfig.json`.

## What is translated

- Text, with the elements and expressions inside it. `Read the <a href="/docs">docs</a>, {name}` is the segment `Read the {0}docs{/0}, {1}`: an inline element or a router link that wraps text becomes a paired placeholder, and an expression, a component without content, or an element such as `<code>` or `<br>` becomes an atomic one.
- The attributes people read, when their value is static: `title`, `alt`, `placeholder`, `label`, `aria-label`, `aria-description`, `aria-placeholder` and `aria-roledescription`.

A sentence ends at an element that can't sit inside one, such as a `<div>` or a component with content, and at a conditional or repeated element. Elements with `translate="no"` stay as they are, so use it for names such as your brand, and so does the content of elements such as `code`, `pre` and `textarea`. Strings in your scripts and in expressions aren't read.

Text keeps the whitespace its framework renders. Its segment is the same text with whitespace collapsed, a `plain` [skeleton](/guide/concepts/skeletons-and-hashes): text runs are `html-block` units and attributes are `prop` units, with the attribute name as their detail. Text that holds placeholder syntax such as `{0}` is left alone, and the plugin warns about it.

## Server rendering

On the server, create one state per request, so that requests never share a locale. Give it the catalog of its starting locale as `messages`, so that the page renders in that locale and hydrates without a mismatch:

```ts
const catalog = await translations.locales[locale]?.()
const diglot = createDiglot({ ...translations, locale, messages: catalog ? { [locale]: catalog } : {} })
```

In SvelteKit, load the catalog in a universal `+layout.ts` and create the state in the root `+layout.svelte` from its data. React hydrates in the starting locale even when the locale changes before hydration ends.

## Development

During `vite dev`, a change to a record reaches the page without a reload, and so does a new translation for text you just wrote.

## Limitations

- React attributes, and text in `<title>` and `<option>`, are translated in function components only, including those passed to `memo()` and `forwardRef()`, where the rewrite can call a hook. Class components and async components can't call it, and the plugin warns about what it leaves out.
- `.jsx` and `.tsx` files are read as React when your Vite config uses the React plugin, and are left alone otherwise, so JSX for another framework, such as Vue JSX or Solid, isn't translated.
- The rewrite adds names that start with two underscores, such as `__diglot`, so keep those names out of your components.
- A component with content that isn't a router link, such as your own link component, ends a sentence, so the text around it is translated in pieces.
- Text in a Vue template written in another language than HTML, such as Pug, isn't translated.
