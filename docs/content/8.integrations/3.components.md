description: Extract the text of your Vue, React and Svelte components at build time and translate it, without keys or $t(). Keep text as it is with the standard translate attribute.

`@diglot/components` extracts the text you write in Vue, React and Svelte components and translates it. You write plain text, with no keys and no `$t()`, and mark what must stay as it is with the HTML [`translate="no"`](https://developer.mozilla.org/docs/Web/HTML/Global_attributes/translate) attribute. Each run of text becomes a [segment](/guide/concepts/segments), so the same text is translated once wherever it appears.

::package-info{name="@diglot/components" directory="packages/components"}
::

The plugin reads each framework with its own compiler, which you install next to the framework:

| Framework | Compiler |
| --- | --- |
| Vue 3 | `@vue/compiler-sfc`, which comes with `vue` |
| React | `oxc-parser` |
| Svelte 5 | `svelte` |

## Add the plugin

Add the plugin to your Vite config, before the plugin of your framework:

```ts [vite.config.ts]
import diglot from '@diglot/components/vite'
import vue from '@vitejs/plugin-vue'
import { defineConfig } from 'vite'

export default defineConfig({
  plugins: [diglot({ translations: './translations' }), vue()],
})
```

`translations` is the directory of your [translations repository](#translate-your-components), relative to the Vite root. Leave it out while you start, and your components render in the source locale, `en` unless you set `sourceLocale`.

The plugin reads every component under the Vite root and builds a catalog for each locale of `diglot.config.ts` from its records. Each translation is [validated](/core/validation) against its segment first: one that fails, or that a reviewer rejected, is left out, and its text stays in the source locale. Each catalog is its own chunk, loaded when your app switches to its locale.

## Create the locale state

`virtual:diglot` holds the source locale and a loader for each catalog. Pass it to `createDiglot()` in the entry of your app:

::code-group

```ts [Vue]
// src/main.ts
import { createDiglot } from '@diglot/components/vue'
import translations from 'virtual:diglot'

const diglot = createDiglot({ ...translations, locale: 'fr' })
createApp(App).use(diglot).mount('#app')
```

```tsx [React]
// src/main.tsx
import { createDiglot, DiglotProvider } from '@diglot/components/react'
import translations from 'virtual:diglot'

const diglot = createDiglot({ ...translations, locale: 'fr' })
createRoot(document.getElementById('root')!).render(<DiglotProvider diglot={diglot}><App /></DiglotProvider>)
```

```svelte [Svelte]
<!-- src/App.svelte -->
<script>
  import { createDiglot, setDiglot } from '@diglot/components/svelte'
  import translations from 'virtual:diglot'

  setDiglot(createDiglot({ ...translations, locale: 'fr' }))
</script>
```

::

`await diglot.setLocale('de')` loads the catalog of a locale and switches to it, and every component re-renders. Deeper in your app, `useDiglot()` in Vue and React and `getDiglot()` in Svelte return the state for a locale switcher. `diglot.subscribe(listener)` calls `listener` after each change, for example to keep `<html lang>` in step. For the types of `virtual:diglot`, add `@diglot/components/client` to `types` in your `tsconfig.json`.

## What is translated

Take this component:

::code-group

```vue [Vue]
<template>
  <p>Hi <b>{{ user.name }}</b>, welcome to <span translate="no">Conduit</span>. Read <RouterLink to="/docs">the docs</RouterLink>.</p>
  <input placeholder="Search articles">
</template>
```

<!-- eslint-skip -->

```tsx [React]
export function Welcome({ user }) {
  return (
    <>
      <p>Hi <b>{user.name}</b>, welcome to <span translate="no">Conduit</span>. Read <Link to="/docs">the docs</Link>.</p>
      <input placeholder="Search articles" />
    </>
  )
}
```

```svelte [Svelte]
<script>
  let { user } = $props()
</script>

<p>Hi <b>{user.name}</b>, welcome to <span translate="no">Conduit</span>. Read <a href="/docs">the docs</a>.</p>
<input placeholder="Search articles">
```

::

In all three, it has the same two segments, with the same hashes. A translator sees the sentence with numbered placeholders in place of the markup, and can move them but not change what they hold:

| Segment | French translation |
| --- | --- |
| `Hi {0}, welcome to {1}. Read {2}the docs{/2}.` | `Bonjour {0}, bienvenue sur {1}. Lisez {2}la documentation{/2}.` |
| `Search articles` | `Rechercher des articles` |

In French, the paragraph renders as:

```html
<p>Bonjour <b>Ada</b>, bienvenue sur <span translate="no">Conduit</span>. Lisez <a href="/docs">la documentation</a>.</p>
```

The name stays reactive and the link stays a router link, wherever the translation puts them.

- **Text** is translated with the elements and expressions inside it. An inline element or a router link that wraps text becomes a paired placeholder, such as `{2}the docs{/2}`. An expression, an element with nothing to translate, a component without content, or an element such as `<code>` or `<br>` becomes an atomic one, such as `{0}`.
- **Attributes** that people read are translated when their value is static:

  | Attribute | Read as |
  | --- | --- |
  | `title` | A tooltip |
  | `alt` | An image description |
  | `placeholder`, `aria-placeholder` | The hint in an empty field |
  | `label` | The text of an `<option>`, `<optgroup>` or `<track>` |
  | `aria-label`, `aria-description`, `aria-roledescription` | What a screen reader announces |

- **Left as it is:** elements with `translate="no"`, Vue elements with `v-pre`, and the content of `code`, `pre`, `kbd`, `samp`, `var`, `svg`, `math`, `script`, `style` and `textarea`. Strings in your scripts and in expressions, such as `{{ ok ? 'Yes' : 'No' }}`, aren't read.

A sentence ends at an element that can't sit inside one, such as a `<div>` or a component with content, and at a conditional or repeated element. Text keeps the whitespace its framework renders, and its segment is the same text with whitespace collapsed. Segments are `plain` [skeletons](/guide/concepts/skeletons-and-hashes): text runs are `html-block` units and attributes are `prop` units, with the attribute name as their detail.

::collapsible{name="the code the plugin compiles"}

The plugin rewrites each component before its framework compiles it. Each placeholder renders the original markup: a slot in Vue, a function in React, and a snippet in Svelte.

::code-group

```vue [Vue]
<template>
  <p><DiglotText h="7cec44fb029a45da" :s="'Hi {0}, welcome to {1}. Read {2}the docs{/2}.'"><template #0><b>{{ user.name }}</b></template><template #1><span translate="no">Conduit</span></template><template #2="{ __children }"><RouterLink to="/docs"><component :is="__children" /></RouterLink></template></DiglotText></p>
  <input :placeholder="$diglot('6f1eddcc5d7df854', 'Search articles')">
</template>
```

<!-- eslint-skip -->

```tsx [React]
import { DiglotText as __DiglotText, useTranslate as __useTranslate } from '@diglot/components/react';
export function Welcome({ user }) { const __diglot = __useTranslate();
  return (
    <>
      <p><__DiglotText h="7cec44fb029a45da" s={'Hi {0}, welcome to {1}. Read {2}the docs{/2}.'} p={[(<b>{user.name}</b>), (<span translate="no">Conduit</span>), __children => (<Link to="/docs">{__children}</Link>)]} /></p>
      <input placeholder={__diglot('6f1eddcc5d7df854', 'Search articles')} />
    </>
  )
}
```

```svelte [Svelte]
<script>
  let { user } = $props()

import { DiglotText as Diglot__Text, translate as __translate } from '@diglot/components/svelte'; const __diglot = __translate();
</script>

<p><Diglot__Text t={$__diglot} h="7cec44fb029a45da" s={'Hi {0}, welcome to {1}. Read {2}the docs{/2}.'}>{#snippet __p0()}<b>{user.name}</b>{/snippet}{#snippet __p1()}<span translate="no">Conduit</span>{/snippet}{#snippet __p2(__children)}<a href="/docs">{@render __children()}</a>{/snippet}</Diglot__Text></p>
<input placeholder={$__diglot('6f1eddcc5d7df854', 'Search articles')}>
```

## Translate your components

Translations are records in a translations repository, the same as for Markdown. List your components in a source of its `sources.yml` and run [`diglot extract`](/workflow/cli/extract), which needs the compilers of your frameworks installed in that repository too:

```yaml [translations/sources.yml]
sources:
  - name: app
    path: ..
    include: ['src/**/*.{vue,tsx,svelte}']
    exclude: ['**/*.test.*']
```

From there your segments are like any others: [machine translation](/machine-translation/overview) drafts them, people [review](/guide/how-to/review-translations) them, and [x18n](/review-ui/overview) finds each one in the files that [`diglot checkout`](/workflow/cli/checkout) exports.

## Server rendering

On the server, create one state per request, so that requests never share a locale. Give it the catalog of its starting locale as `messages`, so that the page renders in that locale and hydrates without a mismatch:

```ts
const catalog = await translations.locales[locale]?.()
const diglot = createDiglot({ ...translations, locale, messages: catalog ? { [locale]: catalog } : {} })
```

In SvelteKit, load the catalog in a universal `+layout.ts` and create the state in the root `+layout.svelte` from its data. React hydrates in the starting locale even when the locale changes before hydration ends.

### Nuxt

Add the plugin to the Vite config of Nuxt. Its root is the `app` directory, so `translations` is relative to it:

```ts [nuxt.config.ts]
import diglot from '@diglot/components/vite'

export default defineNuxtConfig({
  vite: {
    plugins: [diglot({ translations: '../translations' })],
  },
})
```

Then install the runtime in a plugin. Nuxt runs it for each request on the server, and `useState` sends the catalog of the starting locale to the client in the payload:

```ts [app/plugins/diglot.ts]
import { createDiglot } from '@diglot/components/vue'
import translations from 'virtual:diglot'

export default defineNuxtPlugin(async (nuxtApp) => {
  const locale = useCookie('locale').value ?? translations.sourceLocale
  const messages = useState<Record<string, Record<string, string>>>('diglot', () => ({}))
  if (import.meta.server && locale in translations.locales)
    messages.value = { [locale]: await translations.locales[locale]!() }
  nuxtApp.vueApp.use(createDiglot({ ...translations, locale, messages: messages.value }))
})
```

A locale switcher calls `setLocale()` from `useDiglot()` and stores the locale in the same cookie. `NuxtLink` inside a sentence becomes a paired placeholder, like `RouterLink`.

## Development

During `vite dev`, a change to a record reaches the page without a reload, and so does a new translation for text you just wrote.

## Limitations

- React text and attributes are translated in client components only: server components, such as async ones, can't render `<DiglotText>` or call the hook.
- React attributes, and text in `<title>` and `<option>`, are translated in function components only, including those passed to `memo()` and `forwardRef()`, where the rewrite can call a hook. The plugin warns about the ones it leaves out, such as those in class components.
- `.jsx` and `.tsx` files are read as React when your Vite config uses the React plugin, and are left alone otherwise, so JSX for another framework, such as Vue JSX or Solid, isn't translated.
- The rewrite adds names that start with two underscores, such as `__diglot`, so keep those names out of your components.
- A component with content that isn't a router link, such as your own link component, ends a sentence, so the text around it is translated in pieces.
- Text in a Vue template written in another language than HTML, such as Pug, isn't translated.
- Text that holds placeholder syntax such as `{0}` is left alone, and the plugin warns about it.
