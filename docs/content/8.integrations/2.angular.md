title: Angular
description: Show translated Markdown documents in an Angular app, applied from the bundles of a translations repository in the browser and during server rendering.

`@diglot/angular` brings diglot translations into an [Angular](https://angular.dev) app that renders Markdown, such as a documentation site, in-app help or a changelog. You tell it where your bundles and source documents are, and `diglotDocument()` gives your components a document in the current locale. Your app renders the Markdown with whatever renderer it already uses.

::package-info{name="@diglot/angular" directory="packages/angular"}
::

The package needs Angular 22 and Node.js 22 or later. It is for documents, not for the strings of your templates, so it works next to `@angular/localize` or any other i18n library and doesn't replace them.

## Prepare the translations repository

Your app applies translations in the browser, so it reads the bundles that [`diglot build`](/workflow/cli/build) writes, one `dist/<locale>.json` per locale, and the policy snapshot in `.diglot/policy.json` that [`diglot extract`](/workflow/cli/extract) writes. Both have to be up to date when you build your app, so run the two commands before `ng build`, for example in a `prebuild` script:

```json [package.json]
{
  "scripts": {
    "translations": "diglot extract --cwd translations && diglot build --cwd translations",
    "prebuild": "pnpm translations",
    "build": "ng build"
  }
}
```

Set `parser` to `comark` or `mdast` in the translations repository. `satteri` needs native bindings that browsers can't load, so `provideDiglot()` throws when you pass it.

```ts [translations/diglot.config.ts]
import { defineConfig } from '@diglot/core'

export default defineConfig({
  locales: ['fr'],
  parser: 'mdast',
})
```

Serve the bundles and your source Markdown files with your app, for example as assets in `angular.json`:

```json [angular.json]
{
  "assets": [
    { "glob": "**/*", "input": "public" },
    { "glob": "*.json", "input": "translations/dist", "output": "translations" },
    { "glob": "**/*.md", "input": "src/content/docs", "output": "docs" }
  ]
}
```

With `mdast`, also add `"externalDependencies": ["satteri"]` to the build options. The mdast adapter imports Sätteri only when its parser is `satteri`, but the Angular build tries to bundle that import all the same.

## Provide diglot

Add `provideDiglot()` to your application config, next to `provideHttpClient()`:

```ts [src/app/app.config.ts]
import type { ApplicationConfig } from '@angular/core'
import type { PolicySnapshot } from '@diglot/core'
import { provideHttpClient, withFetch } from '@angular/common/http'
import { provideClientHydration } from '@angular/platform-browser'
import { provideRouter, withComponentInputBinding } from '@angular/router'
import { provideDiglot } from '@diglot/angular'
import { withDiglotRouteLocale } from '@diglot/angular/router'
import policy from '../../translations/.diglot/policy.json'
import { routes } from './app.routes'

export const appConfig: ApplicationConfig = {
  providers: [
    provideRouter(routes, withComponentInputBinding()),
    provideHttpClient(withFetch()),
    provideClientHydration(),
    provideDiglot({
      defaultLocale: 'en',
      bundleUrl: locale => `/translations/${locale}.json`,
      sourceUrl: path => `/docs/${path}.md`,
      policy: policy as PolicySnapshot,
      parser: 'mdast',
    }, withDiglotRouteLocale('locale')),
  ],
}
```

| Option | Description |
| --- | --- |
| `defaultLocale` | The locale your documents are written in. They are shown as they are in this locale, without fetching a bundle |
| `locale` | A function that returns the locale to show. It can read signals, and documents follow it when it changes. Defaults to `defaultLocale`, and a locale feature such as `withDiglotRouteLocale()` takes its place |
| `bundleUrl` | The URL of the bundle of a locale |
| `sourceUrl` | The URL of the source Markdown of a document, by the path you pass to `diglotDocument()` |
| `policy` | The policy snapshot in `.diglot/policy.json`. Required |
| `policyFunctions` | The `codeLabel` or `salt` function, when your policy has a custom one. See [snapshots](/core/policy-and-config#snapshots) |
| `parser` | `comark` or `mdast`, the `parser` of your translations repository |

Translations are matched to your documents by their hashes, which only agree under the policy the records were extracted with. `provideDiglot()` restores the snapshot when your app starts and throws when it can't, so a missing or outdated snapshot fails loudly instead of leaving every page untranslated.

### Read the locale from the route

`withDiglotRouteLocale(param)`, from `@diglot/angular/router`, reads the locale from a route parameter, `locale` by default, such as `:locale` in a route for `/fr/guide`. A route without the parameter shows the default locale. The locale changes when a navigation activates its routes, so the components it creates never load a document in the previous locale first, and the page on screen keeps its locale while lazy routes load. Apps without `@angular/router` don't need this import.

To read the locale from somewhere else, pass `locale` instead, for example a signal of your own:

```ts
const locale = signal('en')

provideDiglot({ /* ... */ locale })
```

## Show a document

Call `diglotDocument()` with a function that returns the path of the document, in an injection context such as the field initialiser of a component:

```ts [src/app/page.ts]
import { Component, computed, input } from '@angular/core'
import { diglotDocument } from '@diglot/angular'
import { marked } from 'marked'

@Component({
  selector: 'app-page',
  template: `
    @if (doc.report()?.missing) {
      <aside>This page is only partly translated.</aside>
    }
    <article [innerHTML]="html()"></article>
  `,
})
export class Page {
  readonly slug = input.required<string>()
  readonly doc = diglotDocument(() => this.slug())
  readonly html = computed(() => {
    const body = this.doc.markdown()?.replace(/^---\n[\s\S]*?\n---\n/, '') ?? ''
    return marked.parse(body, { async: false })
  })
}
```

The document loads again whenever its path or the locale changes. It has these signals:

| Signal | Content |
| --- | --- |
| `markdown` | The Markdown to render, frontmatter included, so remove or read the frontmatter before you render the body. `undefined` until the first document has loaded and after an error |
| `report` | The [report](/core/apply) of `apply` for `markdown`: how many segments were applied, missing or rejected. `null` for the default locale, and `undefined` when there is no `markdown` |
| `locale` | The locale of `markdown` |
| `isLoading` | Whether the document is loading |
| `error` | Why the source or the bundle couldn't be loaded or applied |

While the document of another path or locale loads, `markdown`, `report` and `locale` keep the previous document, so your page doesn't go blank and the three always match. `isLoading` tells you that the next one is on its way. After an error, they are cleared.

`reload()` loads the document again, even when the server rendered it.

A translated document is your source document with the locale's translations in place. Text without a usable translation stays in the source language, so a partly translated document is still complete, and rejected translations never appear. Use `report` to tell your readers when a document isn't fully translated. The frontmatter fields that the policy marks as prose, `title` and `description` among them, are translated too. URLs are never translated, so a link to `/en/guide` points to the same address in every locale.

## Bundles and loading

Each locale's bundle is fetched once, the first time a document needs it, and shared by every document after that. A bundle that fails to load is fetched again on the next attempt. The source documents and the bundles are fetched with `HttpClient`, so your interceptors apply to them.

## Server rendering and prerendering

Documents load the same way during server rendering and prerendering, and the server waits for them before it sends the page. The server hands each translated document to the browser through `TransferState`, so the browser shows it while it hydrates without fetching the document or the bundle again. Once the app is stable, documents load from the network, so a document you reload is never replaced by the older copy from the server. The bundles themselves stay out of the HTTP transfer cache, because a bundle holds every document of a locale.

When you prerender, give the route parameters of every page and locale to `getPrerenderParams` in your server routes, and use `withFetch()`, so that the build can read your bundles and documents from its own output.

## Limitations

The package translates Markdown documents, and MDX documents with `mdast` when their path ends in `.mdx`. It doesn't translate the strings of your templates. Your app renders the Markdown itself, so components and other syntax your renderer doesn't know are up to it.
