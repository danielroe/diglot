This page is a reference for the options of `danielroe/diglot/packages/action`. Pass inputs with `with:` and the API key with `env:`.

## Inputs

| Input | Default | Description |
| --- | --- | --- |
| `working-directory` | `.` | Root of the translations repository, where `diglot.config.ts` lives |
| `locales` | every locale with machine translation enabled | Only these locales, separated by commas or spaces |
| `sources` | all sources | Only these sources, separated by commas or spaces |
| `model` | `mt.model`, then `DIGLOT_MT_MODEL` | Model id for the Vercel AI Gateway |
| `ai-gateway-api-key` | the `AI_GATEWAY_API_KEY` environment variable | The gateway key |
| `limit` | none | The most segments per locale sent to the model in one run. The rest wait for the next run |
| `retry-rejected` | `false` | Translate segments that QA rejected in earlier runs again |
| `commit` | `true` | Commit the changes. With `false`, the files stay in the working tree |
| `build-dist` | `true` | Build `dist/<locale>.json` and add it to the commit |
| `git-user-name` | `diglot[bot]` | The commit author name |
| `git-user-email` | `diglot[bot]@users.noreply.github.com` | The commit author email |

A `sources` value that names an unknown source fails the run and lists the configured sources.

## Outputs

| Output | Description |
| --- | --- |
| `translated` | Segments translated from scratch |
| `updated` | Translations updated from their predecessor |
| `carried` | Translations carried over from their predecessor |
| `rejected` | Segments rejected by QA |
| `costUsd` | The model cost in USD, when the provider reports it |
| `committed` | `true` when a commit was made |
| `sha` | The new commit |

All values are strings, so compare with `== 'true'`. The usual use is the push step:

```yaml
- if: steps.diglot.outputs.committed == 'true'
  run: git pull --rebase origin ${{ github.ref_name }} && git push
```

## The job summary

Every run writes a summary to the job page. It has a table per locale with machine translation on or off, the counts of translated, updated, carried, rejected, skipped and deferred segments, the requests, the tokens in and out and the cost. A second table lists each source with its revision range and how many segments were added, removed and modified. Segments rejected by QA are listed below that with their issues, up to 100.

The `Skipped` column counts the live segments of a locale whose record a reviewer rejected. `Deferred` counts the segments that `limit` left for a later run.
