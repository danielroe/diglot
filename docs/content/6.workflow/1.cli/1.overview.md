`@diglot/cli` provides the `diglot` command. It covers the parts of the workflow that don't need a model: fetching sources, extracting segments, reporting changes, checking records and building the bundles your site reads. Machine translation is the job of the [Action](/workflow/action/overview).

Run it without installing anything, or add it to a project:

```bash
pnpm dlx @diglot/cli <command>
```

::package-info{name="@diglot/cli" directory="packages/cli" install="pnpm add -D @diglot/cli"}
::

It needs Node.js 22.18 or later. Once installed, call `diglot` from your scripts.

## Commands

| Command | What it does |
| --- | --- |
| [`diglot checkout [sources...]`](/workflow/cli/checkout) | Exports each source as plain files under `.diglot/sources/<source>` |
| [`diglot extract`](/workflow/cli/extract) | Extracts the segments of each source and writes its manifest |
| [`diglot diff`](/workflow/cli/diff) | Shows added, removed and modified segments compared with the manifests |
| [`diglot validate`](/workflow/cli/validate) | Checks every record against its source segments |
| [`diglot build`](/workflow/cli/build) | Writes `dist/<locale>.json` for each locale |
| [`diglot status`](/workflow/cli/status) | Reports translation coverage per locale and source |

## The working directory

Every command reads `diglot.config.ts` and `sources.yml` from the directory given with `--cwd`, which defaults to `.`. Run the command from the root of your translations repository, or pass the path:

```bash
pnpm dlx @diglot/cli status --cwd ../translations
```

## A typical sequence

After a source changes, `extract` refreshes the manifests, `status` shows what is missing, and `validate` and `build` prepare the output. `diff` is the one to run before `extract` when you want to see what changed, because it compares against the manifests that `extract` overwrites.

```bash
pnpm dlx @diglot/cli diff
pnpm dlx @diglot/cli extract
pnpm dlx @diglot/cli validate
pnpm dlx @diglot/cli build
```

The Action performs the equivalent steps itself, so you only need the CLI for local work, for CI checks, and for building bundles when the Action's `build-dist` is `false`.
