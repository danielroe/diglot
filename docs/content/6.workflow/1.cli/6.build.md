---
title: build
description: Write one JSON bundle per locale from the records your sources use.
---

`diglot build` collects the records of each locale into `dist/<locale>.json`, the file your site reads when it applies translations. Every bundle has the form `{ version, locale, records }`, with records keyed by hash.

```bash
pnpm dlx @diglot/cli build [--locale fr] [--all]
```

## Options

| Option | Default | Description |
| --- | --- | --- |
| `--locale` | all locales | Build only this locale |
| `--all` | off | Include records that no source uses |
| `--cwd` | `.` | The translations repository root |

By default a bundle contains only the records whose hash appears in a manifest. If there are no manifests at all, every record is included. The output directory is `dist` unless you set `outDir` in the [configuration](/guide/how-to/configure).

## Output

For each locale, the command prints the number of records, how many of them a reviewer rejected, the path, and how many unused records it skipped:

```text
fr: 1204 records (3 rejected) -> dist/fr.json (88 unused skipped)
```

The numbers are examples of the format. Rejected records are part of the bundle on purpose, so a site can show their status. Applying the bundle still falls back to the source text for them, as [review and status](/guide/concepts/review-and-status) explains.
