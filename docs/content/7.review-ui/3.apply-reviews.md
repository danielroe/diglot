---
title: Apply reviews
description: Move x18n approvals onto diglot records as verified translations.
---

`x18n review approve` only writes the approval into `.x18n/reviews.yml`. A diglot record becomes `verified` only after you copy the approval onto it, which the bundled `diglot-x18n` binary does.

```bash
pnpm exec diglot-x18n apply-reviews
```

## What it changes

The command reads `.x18n/reviews.yml` and looks at the review thread of each hash and locale. A record becomes `review: 'verified'` when the last open approval or change request in its thread is an approval that carries the record's current text. A change request or a suggestion leaves the record as it is. So does an approval without a text, and an approval of a different text than the record holds, because the reviewer didn't approve what readers would see.

The verification goes through `verifyRecord` from [`@diglot/core`](/core/review), so the same rules apply as anywhere else. A rejected record isn't verified, because only an edit replaces a rejection. A record that is already verified keeps its first reviewer. A verified record gets `verifiedBy` with the reviewer and the time of the approval, and its `updatedAt` is set to that time.

## Who the reviewer is

`verifiedBy.by` is taken from, in order:

1. The `--reviewer <login>` option.
2. The `GITHUB_ACTOR` environment variable.
3. The result of `gh api user --jq .login`.
4. The git `user.name`.

If none of these gives a name, the author of the approval in x18n is used.

## Commit the result

The command prints the record files it changed. Commit them together with `.x18n/reviews.yml`.

`applyReviews(root, reviews, reviewer?)` is exported for scripts that want the same behaviour, and returns the paths it wrote.
