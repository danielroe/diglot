---
title: QA checks
description: Look up the model-free checks that decide whether a machine translation is accepted.
---

A language model can return text that looks fine and still breaks a page. `runQa` catches the failures that can be detected without a model, so every machine translation is checked in the same way, whichever model produced it.

```ts
import { runQa } from '@diglot/mt'

const issues = runQa(translation, segment, { locale: 'fr', glossary, style })
```

It returns a list of `{ check, severity, message }`. An `error` rejects the output and triggers a retry. A `warning` is accepted and reported for reviewers.

## Checks

| Check | Severity | Rule |
| --- | --- | --- |
| `grammar` | error | `validate` from `@diglot/core` passes: no markup outside the [translation grammar](/core/validation), and plain segments stay plain |
| `placeholders` | error, warning | Every placeholder is present and paired. Repeated code placeholders are a warning. Text shaped like a placeholder (`｛1｝`, `[1]`, `<1>`, `$1`) that the source doesn't have is an error |
| `untranslated` | error, warning | Output identical to a source with three or more translatable words is an error. Output that is mostly source words is a warning |
| `length-ratio` | warning | The length falls outside the band for the locale |
| `leaked-instructions` | error | Words such as "translation", "placeholder", "voici la", code fences or JSON keys that the source doesn't have |
| `structure` | error, warning | Heading markers in a heading are an error. A changed line count is a warning |
| `numbers` | error, warning | Version strings and multi-digit numbers must be kept (error). Single digits are a warning |
| `emphasis` | error, warning | Emphasis markers that cannot open or close under CommonMark flanking rules, such as `_` inside a word or `**` between punctuation and CJK text. A warning when the source has such markers too |
| `glossary` | warning | See [Glossary and style](/machine-translation/glossary-and-style) |
| `response` | error | The model's answer lacks the segment or doesn't match the schema |

Glossary terms that are kept untranslated don't count as source words in the `untranslated` check.

## Length bands

The `length-ratio` check compares the length of the translation with the source, ignoring placeholders and extra whitespace, and applies only to sources of 25 characters or more. The default bands are:

| Language | Range |
| --- | --- |
| `fr`, `es`, `it`, `pt` | 0.85 to 1.7 |
| `de` | 0.85 to 1.8 |
| `ru` | 0.8 to 1.7 |
| `ja` | 0.25 to 0.9 |
| `zh` | 0.2 to 0.8 |
| `ko` | 0.3 to 1 |

Other languages have no default band. Set `lengthRatio` in `<locale>/style.yml` to add or change one.

## What happens to issues

[`translateSegments`](/machine-translation/translate-segments) and [`updateTranslation`](/machine-translation/update-translation) retry on errors and reject after the last attempt. The [Action](/workflow/action/rejected-and-skipped) stores the error messages of rejected segments in `.diglot/rejected/<locale>.json`.
