---
title: Manifests
description: Create, write and read the manifests that record each source's segments.
---

A manifest lists the segments of every file of one source at one revision. Comparing a fresh extraction with the stored manifest is how diglot finds [what changed](/guide/concepts/keeping-in-sync).

## Shape

```json
{
  "version": 1,
  "source": "nuxt-main",
  "ref": "main",
  "sha": "<commit>",
  "policy": "<fingerprint>",
  "files": {
    "docs/guide/intro.md": [
      { "hash": "...", "kind": "paragraph", "format": "markdown", "words": 9, "skeleton": "..." }
    ]
  }
}
```

Each entry has the `hash`, `kind`, `format`, `words` and `skeleton` of a segment, plus `placeholders` (their types by id) and `salt` when there are any. The ids and types are enough to validate a translation without parsing the document again, which is what `validationTarget(entry)` returns for `validate`.

## Functions

| Function | Description |
| --- | --- |
| `createManifest(source, files, { ref?, sha?, policy? })` | Builds a manifest from extracted segments, with files sorted by path |
| `manifestPath(stateDir, source)` | The path `<stateDir>/manifest/<source>.json` |
| `serialiseManifest(manifest)` | Text with one entry per line, so diffs show changed segments |
| `writeManifest(stateDir, manifest)` | Writes the manifest and returns its path |
| `readManifest(stateDir, source)` | One manifest, or `undefined` if there is none. An unsupported version throws |
| `readManifests(stateDir)` | Every manifest in the state directory, sorted by file name |
| `liveHashes(manifests)` | The set of hashes used by any file of the given manifests |
| `validationTarget(entry)` | What `validate` needs to check a translation of an entry |

`policy` is the `policyFingerprint` of the policy the segments were extracted under. `diglot extract` and the Action set it and write the policy itself to `.diglot/policy.json` with `writePolicy(stateDir, policy)`, which `readPolicy(stateDir)` reads back. Together they let a server check that it extracts with the same policy as the manifests. See [snapshots](/core/policy-and-config#snapshots).

`createManifest`, `serialiseManifest`, `validationTarget` and `liveHashes` are also exported from `@diglot/store/runtime`.

A hash is *live* when some manifest uses it. Records whose hash isn't live are unused: they stay in git, and bundles leave them out by default.
