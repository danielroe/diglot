## Records

Records are stored one per file at `<locale>/segments/<hh>/<hash>.json`, and these functions work with them:

| Function | Description |
| --- | --- |
| `recordPath(locale, hash)` | The path relative to the repository root |
| `readRecord(root, locale, hash)` | One record, or `undefined` if the file doesn't exist |
| `writeRecord(root, locale, record)` | Validates the record, writes it and returns its path |
| `readRecords(root, locale)` | Every record of a locale, sorted by hash |
| `loadLocale(root, locale)` | The same records in a `Map` keyed by hash |

`serialiseRecord` produces the file content: a fixed key order, two-space indentation and a trailing newline. Records are validated on read and write, and `readRecords` throws when a file is malformed or when a record's hash doesn't match its path, so a hand edit that breaks a record is caught early.

## Build bundles

`build(root, { locales, outDir?, only? })` writes `<outDir>/<locale>.json` for each locale and returns one result per locale. `outDir` is relative to `root` and defaults to `dist`. When `only` is given, only records with those hashes are included, typically `liveHashes` of all manifests.

Each result has `locale`, `path`, `records` (the count in the bundle), `rejected` (how many of those a reviewer rejected) and `skipped` (how many records were left out because their hash isn't live).

The bundle has the shape `{ version: 1, locale, records }`, with records keyed by hash.

## Parse a bundle

`parseBundle(content)` accepts the text of a bundle or the parsed object and returns a `Map<hash, record>`. It validates every record, throws `unsupported locale bundle` for an unknown version, and throws when a key doesn't match its record's hash. Bundles include rejected records so that consumers can show their status, and applying them still falls back to the source text. See [use translations in your site](/guide/how-to/use-translations).
