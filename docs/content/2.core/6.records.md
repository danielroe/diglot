title: Records
description: Create, parse and classify translation records.
---

The [fields of a record](/guide/concepts/translation-records) are defined by the `TranslationRecord` type. These functions create and check them.

| Function | Description |
| --- | --- |
| `parseRecord(value)` | Checks the shape of an unknown value and returns it as a record. Throws `RecordError` |
| `createRecord({ segment, text, origin, ... })` | Fills the identity fields (`hash`, `source`, `salt`) from the segment and returns a normalised record |
| `normaliseRecord(record)` | Returns a copy with keys in `RECORD_KEYS` order and undefined fields dropped |
| `recordStatus(record, segment?)` | The status a reader sees |
| `editRatio(record)` | The share of the machine candidate that reviewers changed |

## Parsing

`parseRecord` rejects unknown keys, a hash that isn't 16 hexadecimal characters, empty required strings, unknown values of `origin`, `review` and `derived`, and a missing `prev` when `derived` isn't `fresh`. It requires `verifiedBy` when `review` is `verified`, and `rejectedBy` when it is `rejected` and only then. The error message starts with the record's hash when it has one.

## Creating

`createRecord` defaults `review` to `none`, `derived` to `fresh` (or `update` when `prev` is set) and `updatedAt` to now.

```ts
import { createRecord } from '@diglot/core'

const record = createRecord({
  segment,
  text: 'Nuxt est propulsé par {0}Nitro{/0}.',
  origin: 'mt',
  mt: { model: 'anthropic/claude-sonnet-5.5', candidate: 'Nuxt est propulsé par {0}Nitro{/0}.' },
})
```

## Status

`recordStatus(record, segment?)` returns `untranslated`, `machine`, `pending-review`, `edited`, `verified` or `rejected`, following the rules in [review and status](/guide/concepts/review-and-status). When you pass a segment, the record's text is validated against it and a failure yields `rejected`.

## Edit ratio

`editRatio(record)` returns a number from 0 to 1, or `undefined` when the record has no `mt.candidate`. It is one minus the similarity between the candidate and the current text, so `0` means the reviewer changed nothing.

## Rejecting a translation

A rejected record has `review: 'rejected'` and `rejectedBy: { by, at }`. Readers then see the source text, and machine translation leaves it alone. An edit (`review: 'edited'` without `rejectedBy`) or a new source hash replaces the rejection. To make these changes from code, use the functions on the [review](/core/review) page, which check each transition for you.
